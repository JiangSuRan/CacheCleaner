# CacheCleaner 性能评估与 Rust 原型对照

2026-10-16：已采纳本报告的 C# 优化，正式本地构建为 `publish/CacheCleaner.exe`（5.1.2）。下述数据保留原测量版本与样本，不作为新版本的重新测量结果。

结论：先采用本轮 C# 优化，保留 Rust 只读原型用于后续研究，暂不迁移正式清理引擎。扫描改进已在现有语言内取得；Rust 在当前固定目录上相对已有 C# 求和实现的差距不足以证明全量重写的收益。

## 方法与范围

- 基础提交：`988e77e`，应用 5.1.1；两组加入相同、按需启用的诊断计时。候选版本在此基础上减少元数据重复查询和项目标记重复匹配。
- 环境详情在各 JSON 的 Environment 字段。Rust 为 1.99.0 MSVC，Release，LTO，单线程、无第三方 crate；C# 为 .NET 10 Release。对照未启用额外扫描并发。
- 本机只读扫描三轮交替顺序：before/after、after/before、before/after。未清空操作系统缓存，不用于估计冷启动或冷缓存性能。
- 完整扫描指顺序调用 ScanAll 与 ScanAutoDiscovered 的后台 API，不含界面绘制、进度回调、表格排序及 MainForm 的结果日志写入；不能直接等同于用户点击到画面完成的耗时。
- 固定目录含 24,576 个文件、49,922,048 字节、中文和空格路径。每种操作每轮测 7 次，共 21 个样本。Measure/SumFiles 与 Rust 均先预热；Preview/Projects 的首个样本可能含方法或注册表初始化开销，纳入原始样本及中位数统计。Rust 和 C# 的计时均不含进程启动。
- 真实删除仅在 Regression 自建测试目录内验证；本轮不测量本机系统清理速度，也不运行 DISM 清理、删除真实缓存或修改用户设置。

## 结果

| 测量项 | 原 C# 中位数 | 优化 C# 中位数 | Rust 原型中位数 |
|---|---:|---:|---:|
| 本机完整扫描，3 次 | 10.890 秒 | 6.689 秒 | 未实现 |
| 完整扫描 CPU 时间，3 次 | 8.734 秒 | 4.906 秒 | 未测量 |
| 完整扫描累计托管分配，3 次 | 294,255,640 B | 235,790,416 B | 不适用 |
| 固定目录剩余量统计，21 次 | 126.49 ms | 15.37 ms | 8.75 ms |
| 固定目录无保留期预览，21 次 | 126.51 ms | 17.69 ms | 未实现 |
| 固定目录已有 SumFiles 求和，21 次 | 9.54 ms | 9.35 ms | 8.75 ms（目录计量） |
| 固定目录项目识别遍历，21 次 | 25.99 ms | 18.58 ms | 未实现 |

完整扫描中位耗时下降约 38.6%，但本机波动明显：原版范围 8.049–12.358 秒，优化版 6.552–10.463 秒。三次样本不构成稳定性能保证；不能把中位数比值当作所有机器的提速比例。六次扫描均为 135 个已知扫描记录、12 个自动发现记录，目标名称、路径、风险和存在状态的 SHA-256 摘要一致；实时文件大小未纳入身份摘要。

原版阶段中位耗时最高的是项目识别（约 4.556 秒）与自动发现（约 2.405 秒）；优化后分别约 2.179 秒、1.299 秒。CPU 时间与分配也下降，说明并非只有磁盘等待，目录匹配和重复元数据处理同样值得优化。

权衡：固定目录剩余量统计的托管分配由约 7.19 MB 增至 8.57 MB。此处以更多带元数据的 FileInfo 对象换取较少系统查询，并未实现“所有场景内存都更少”。

## 实现与边界

- 项目识别每个目录只构建一次文件名集合，保留类型优先级、大小写、主/附加标记、后缀及原有活跃度分级。
- 自动发现复用目录枚举取得的名称和属性，继续跳过 reparse point；不增加扫描根、深度、规则或清理范围。
- 剩余量统计及无保留期预览复用文件枚举元数据。[.NET 文档](https://learn.microsoft.com/en-us/dotnet/api/system.io.directoryinfo.enumeratefiles)说明返回的 FileInfo 已预填 Length 等属性。实际删除及保留期判断前仍 Refresh，不以陈旧时间决定是否删除。
- Rust 原型采用标准库 read_dir；[Rust 文档](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata)说明 Windows 上 DirEntry.metadata 无需额外系统调用。它只完成目录计量，不具备生产清理语义，当前对照也不覆盖链接、访问失败、取消等全部边界的一致性。
- 不将 Rust 原型的小程序体积与含完整 UI、运行时和规则资产的 C# 软件体积比较；不从该原型推断整机清理速度。
